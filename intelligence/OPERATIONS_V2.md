# RISE Intelligence 2.0 — 운영 단순화 및 자동화 전환 (2026-10-16)

## 최종 목표
시장 데이터 수집 → 신선도·원천 검증 → 신호·레짐 사전관문 → Daily 최종 판단 → 기존 RISE ETF·상품기획 연결 → 한 번의 원자적 게시. 기존 00~07 연구 규정 및 원천 이력을 보존한다.

## 실제 저장소 확인
- 이미 존재하는 단일 게시기: `scripts/update_intelligence_portal.py` (snapshot+narrative 입력, 일별/latest/archive/HTML 생성, 동일일자 이전 JSON vintage 저장)
- 검증기: `scripts/validate_intelligence_snapshot.py` 및 `tests/test_intelligence_portal.py`
- 검증 워크플로: `.github/workflows/intelligence_portal_validate.yml`은 수동·PR만 실행. 매일 예약 자동 게시가 아니다.
- 원천 데이터 예약 실행: `daily_update.yml`, `gclri_market_update.yml`, `master_update.yml` 등은 별도 실행. `refresh_pages.yml`은 일부 수집 워크플로 완료 후 Pages 빌드를 요청한다.
- 현재 Daily 작성·검증·게시를 하나로 묶는 예약 오케스트레이터는 확인되지 않았다. 따라서 데이터 수집 성공과 Daily 발행 성공은 별개이다.

## 즉시 적용할 설계 원칙
1. 기존 게시기를 재사용한다. 보고서 HTML·일별 JSON·latest·archive를 GitHub API로 개별 수동 갱신하지 않는다.
2. 단일 일자별 입력 패키지: `snapshot.json` + `report.txt` + 내부 데이터 vintage/원천 근거. 모든 분석은 원천 관측일과 발행일을 구분한다.
3. 원천 데이터·신호·에피소드·레짐 관문·검증 상태를 분리한다. 레짐 관문은 최종 의사결정이 아니다.
4. `SUMMARY_ONLY`는 복구·호환 용도이며, 정기 자동 발행은 기존 검증기가 요구하는 `FULL` 형식으로 한다.
5. 게시 전 검증: 스키마, 동일일자 vintage, HTML 생성, 모든 보관일 JSON/링크, 원천 신선도, 외부 근거, 프레임워크 승격 여부.
6. 게시 원자성: 임시 작업 디렉터리에 전체 결과 생성 → 검증 통과 → 한 커밋으로 게시. 실패 시 latest/archive는 이전 정상본 유지.
7. 동일일자 수정은 원본 및 이유를 vintage에 남긴다. 이전 결론을 조용히 덮어쓰지 않는다.
8. 보고서가 없거나 외부 근거가 불충분하면 실패/부분 성공으로 명시한다. 자동으로 시장 전망을 만들어내지 않는다.

- 기존 게시기와 테스트를 로컬/CI에서 실행해 정상 동작 기준선 확보

- `intelligence_portal_validate.yml`의 보관 링크 및 latest/date 정합성 검사 강화
- `report_status`와 실제 HTML 존재 여부를 일치시킨다

### P1 — 하루 한 번 실행
- 기존 수집 워크플로가 완료된 뒤 단일 Daily 실행을 시작하는 오케스트레이터 추가
- 자료 신선도 기준 미달·검증 실패 시 보고서를 게시하지 않고 장애 로그만 기록

- Daily 요약 + 반론/반증 + RISE 상품 연결 + 신규 ETF 후보의 근거와 상품 중복 검증
- Flow는 원천·투자자 유형·시장폭·집중도·지속성 교차확인 전까지 미확정 유지
- RS는 가격 조정·배당·거래일·환율 정합성 검증 전까지 연구용

## 변경 통제
이번 문서는 설계·감사 기록이며 자동화 배포 완료를 뜻하지 않는다. `.github/workflows`, `scripts`, `data` 변경은 별도 구현·테스트 후 수행한다. 운영 중인 수집기·레짐·검증 규칙을 임의 수정하지 않는다.

## P0 구현·운영 경계 (2026-10-16)

게시기는 기존 portal을 임시 디렉터리에 복사하고 보고서·daily/latest·archive·framework history·vintage를 모두 만든 다음 전체 보관 링크와 latest 정합성을 검증한다. 검증 전에는 기존 portal을 수정하지 않는다. 작업 디렉터리 교체 중 예외는 이전 디렉터리로 rollback한다. 과거 날짜 보완 시 latest는 최신 날짜를 유지한다.

동일 날짜 snapshot 또는 HTML 수정은 `--revision-reason '수정 이유'`가 필요하다. 이전 JSON·HTML·수정 이유는 `data/vintages/<date>/<UTC timestamp + UUID>/`에 함께 보존한다. 기존 vintage 형식도 삭제하지 않는다. 동일 입력 재실행은 신규 vintage를 생성하지 않는다. FULL만 정기 게시하며 빈 본문은 차단한다. 과거의 명시적 SUMMARY_ONLY/pending 기록은 그대로 허용한다.

**원자성 경계:** 이 스크립트는 Git checkout용이다. 두 번의 디렉터리 rename 사이에는 짧은 공백이 있으므로 live HTTP 디렉터리를 직접 대상으로 사용하지 않는다. 검증된 전체 변경을 한 Git 커밋으로 push하고 Pages가 그 커밋을 배포해야 공개 게시가 일관된다. P0는 자동 commit/push나 Pages 배포 성공을 보장하지 않는다.

**강제 종료 복구:** 일반 예외는 rollback하지만 SIGKILL/전원 중단은 보장하지 않는다. 형제 경로 `.intelligence.publish.lock`가 남으면 재실행을 차단한다. 실행 중인 프로세스가 없는지 먼저 확인하고 `.intelligence.backup-*`와 `.intelligence-stage-*`를 검사한다. portal이 없으면 정상 backup을 intelligence로 복구하고 전체 검증을 실행한다. portal이 존재하면 전체 검증 및 Git diff로 정상 여부를 확인한다. 검증 전에는 commit/push하지 않는다. 원본 보존 후 잔여 lock를 제거한다. 백업과 임시 데이터는 자동으로 연구 원본 대신 사용하지 않는다.

재검증:
```bash
python -m unittest tests.test_intelligence_portal tests.test_intelligence_publish -v
python -m unittest discover -s tests -v
```

P1에서는 수집·분석·FULL 보고서 생성 및 신선도/외부 근거 관문을 연결하고, 성공한 게시 전체를 한 커밋으로 저장해야 한다. 현재 P0의 문서/HTML 검사만으로 분석 근거·프레임워크 승격의 타당성이 검증된 것으로 취급하지 않는다. 기존 신호·GCLRI·RS 및 연구 규칙은 변경하지 않았다. 저장소에서 별도 00~07 전체 헌법 원문 묶음은 확인되지 않았으며 운영 문서·레지스트리·테스트에 구현된 기준을 확인했다.

## P1 실행 연결
`intelligence_daily.yml`이 GCLRI 수집 완료 후 기존 4개 엔진을 순서대로 실행하며, `run_intelligence_daily.py`가 입력 vintage·신선도·FULL 패키지·연구 권한을 점검한다. 각 엔진의 기존 workflow는 수동 복구용이다. 정상 FULL 패키지가 없으면 이전 보고서를 유지하고 BLOCKED를 기록한다. 실제 분석/보고서 작성 자동화가 완료됐다는 의미는 아니다. 실행·복구·입력 계약과 남은 과제는 `P1_HANDOFF.md`를 따른다.

## 자동 연구 초안과 엄격한 정식 게시 경계 (2026-10-19)
`build_intelligence_research.py`는 일일 엔진 뒤에 원천 관측·신호·반론·미완료 평가를 자동 작성한다. `data/intelligence/research/<date>/<content hash>/`에 JSON/Markdown을 함께 남긴다. 같은 입력과 본문은 같은 경로이며 변경본은 별도 경로에 보존한다. 엔진 결과의 실행 시각까지 입력 hash에 포함되므로 새 계산 실행은 별도 근거본이다. 이것은 `RESEARCH_DRAFT`이며 FULL 보고서를 대신하거나 latest/archive를 갱신하지 않는다. RISE 연결은 관측일을 확인한 KRX 상품명 일치 조사 목록이며 실제 노출·투자자 수급·경쟁상품 검증이나 외부 마케팅 메시지 승인을 뜻하지 않는다. 원천 차단이 있으면 상품 연결도 보류한다.

게시 입력 검증은 등록된 필수 시계열 누락·비유한 수치·등록 기준보다 완화된 payload 신선도·계산 단계의 원천 시각 불일치를 차단한다. 원천/규칙뿐 아니라 신호·에피소드·관문·검증 결과·KRX 목록까지 SHA256으로 입력 패키지에 결속한다.

**검토본 게시:** 엔진을 다시 실행하면 계산 파일의 timestamp/hash가 달라진다. 정식 검토는 자동 실행이 커밋한 `daily_input.json.source_hashes`를 기준으로 수행하고 해당 날짜 inbox 패키지를 커밋한 뒤 `intelligence_daily.yml`을 `publish_prepared=true`로 수동 실행한다. 또는 `python scripts/run_intelligence_daily.py --publish-prepared`. 이 모드는 계산을 재실행하지 않으며 현재 모든 파일의 hash·원천 연결·신선도·FULL 계약을 다시 검증한다. 원천/계산 결과가 바뀌면 차단하므로 새 근거로 재검토해야 한다. inbox push 자체가 계산을 재실행해 검토본을 무효화하던 경로는 제거했다. 수집 후 자동 실행은 계속 네 엔진을 실행한다. 완전한 FULL 최종판단 자동 작성은 아직 미완료다.

실행 workflow는 현재 run_id/attempt와 일치하는 영수증만 저장·업로드한다. 이전 실행의 성공 기록을 이번 실행 결과로 취급하지 않는다.

## P1 자동 발행 계약 개정 — FULL 1.1 (2026-10-19)
사용자 지시(정식 자동 작성·지연 처리·최종 발행 검증)에 따라 보고서 완결성과 시장판단 확정 여부를 분리한다. 1.0 수동 FULL 및 과거 SUMMARY_ONLY 검증은 변경하지 않는다. 신규 1.1은 `BOUNDED_RESEARCH_V1` 자동 연구 보고서이며 10개 본문 영역(변화·범위·레짐·전달/반증·반대증거·RISE 연결·수급/경쟁/상품·미산정 항목·다음 조치·원천 감사표)을 작성한다. FULL은 본문과 감사표가 생성됐음을 뜻하며 모든 시장판단이 검증됐음을 뜻하지 않는다.

- 신뢰도는 null+이유, 흡수력/스트레스/수급 종합평가는 UNRESOLVED+이유. 과거 숫자 이월 금지. 기존 레짐은 원래 기준일과 “오늘 재확정 아님”을 표시한다. 신규 레짐·규칙·매매 권한 승격은 차단한다.
- 신호 원본의 관측일/값이 현재 원천과 일치해야 판단표에 사용한다. 원천 URL, 관측일, 변화량, 신호 품질, 대안 설명, 반증 점검, 연구 경로를 기록한다. RISE 연결은 KRX 상품명 기반 조사 후보이며 실제 편입노출·투자권유 아님을 명시한다. 수급/경쟁/신상품 판단은 근거 수집 전 보류한다.
- **지연 처리 변경:** 원천 신선도 기준은 그대로다. DTWEXBGS만 유한 수치·유효 관측일·14일 이내·CURRENT/STALE 상태일 때 최신 달러 판단에서 제외하고 PARTIAL 보고서를 허용한다. 14일은 원천 신선도 완화가 아니라 제한적 보고의 최대 허용 공백이다. 달러와 연결된 신호는 판단표/상품 연결에서 제외한다. 원천 자체를 CURRENT로 바꾸거나 값을 보간하지 않는다. 누락·오류·미래값·14일 초과, 다른 등록 시계열의 지연, 수집/계산 원천 불일치, 상위 수집 실패는 전체 게시 차단한다.
- 일일 CLI는 기존 수동 inbox가 없을 때 자동 패키지를 생성한다. 수동 inbox가 있으면 미완성/오류여도 덮어쓰거나 자동 보고서로 우회하지 않는다. 검토본 게시 모드는 기존과 같다.
- 1.1 패키지는 현재 입력으로 snapshot·본문·외부 근거를 다시 생성해 정확히 대조한다. content hash만 재작성해 임의 주장을 넣을 수 없다. 외부 근거는 기존 FRED/KRX 수집에서 사용한 원천을 가리키며 별도 실시간 웹 검증을 했다는 뜻이 아니다.
- 실행시각이 달라도 분석에 사용한 관측·신호·목록·작성 규칙이 같으면 동일 보고서다. 동일일자 실질 변경 시 기존 JSON/HTML과 수정 이유를 vintage에 보존한다. 실행별 원천 hash와 계산 원본은 daily_input/실행 artifact에서 추적한다.

이 개정은 보고서 게시를 가능하게 하는 명시적 계약 변경이다. 포털은 “자동 연구 보고서/일부 분석 제외/미산정”을 표시한다. 상품 추천·확률 추정·투자자 수급·경쟁상품 분석까지 완성한 것으로 표시하지 않는다.

## 사용자 지시 반영 — 기준일 자료 보고 FULL 1.2 (2026-10-20)
사용자는 지연 자료도 “몇 월 며칠 종가/관측값 기준”을 표시하고 보고서를 계속 발행하도록 지시했다. 1.2 `DATED_OBSERVATIONS_V1`부터 달러 전용 14일 제한을 새 보고서에 적용하지 않는다. 기존 1.0/1.1 기록과 검증은 보존한다.

- 정상적인 최근 수집(status SUCCESS, errors 없음, 기존 36시간 수집 신선도 통과)에서 확보된 유한 관측값·유효 과거 날짜가 수집 시계열 마지막 행과 일치하면 지연 기간에 관계없이 기준일 수준 설명에 사용한다. 이 조건은 원천의 실제 발표 지연 원인까지 확정한다는 뜻이 아니다. 보고서에는 “최신 확보 관측”만 표시한다.
- `coverage.dated_context`에 값·단위·기준일 문구·보고일 대비 경과일·직전 관측일과 변화량을 기록한다. 과거 변화량은 같은 수집 응답 내 직전 유효 관측과 비교하며 오늘의 변화로 표현하지 않는다. 원천 신선도 상태는 변경하지 않는다.
- 신선도 미달 자료는 오늘의 신호·동시점 교차확인·ETF 신호 연결에 사용하지 않는다. 모든 자료가 지연돼도 검증된 기준일 자료 보고는 가능하되 최신 판단표와 ETF 연결은 비우고 오늘의 판단 보류를 명시한다.
- 누락, 수집 오류, 비유한 값, 미래 날짜, 수집 파일과 이력의 불일치, 오래된 수집 실행, 상위 수집 실패는 여전히 전체 게시를 차단한다. 실제 네트워크 수집 실패를 날짜 표시로 숨기지 않는다.
- 종가로 정의된 자료만 종가로 표기한다. 현재 GCLRI 목록 중 VIXCLS는 FRED의 Daily, Close 메타데이터(https://fred.stlouisfed.org/series/VIXCLS, 2026-10-20 확인)에 따라 “종가 기준”; 금리·달러·원유 현물·준비금 등은 “관측값 기준”이다. 수집기는 원천 URL·수집시각·성공 상태도 기록한다.
- 포털은 “일부 분석 제외” 대신 신규 보고서에 “자료별 기준일 명시”를 표시한다. 실행 영수증의 dated_context는 기준일 자료 목록이며 실패 목록이 아니다. 원문·JSON·근거를 다시 생성하여 대조하는 검증과 동일일자 이전본 보존은 유지한다.
